# Отчёт
## Тема: упаковка веб-приложения в Docker

Проект: интернет-витрина Tamsun Group.  
Задача: собрать сайт, сервер и базу так, чтобы приложение запускалось одной командой на любом компьютере с Docker Desktop.

## 1. Цель работы

Показать, зачем приложению нужен Docker, из каких частей состоит упаковка и как работает каждый файл этой упаковки.

Без контейнера на новом компьютере нужно отдельно ставить Node.js, PowerShell 7, библиотеку SQLite для нужной системы и собирать сайт командой `npm run build`. Версии легко разъезжаются. Docker собирает всё это в один образ и запускает одинаково.

## 2. Что такое Docker

Docker запускает программу в контейнере: отдельной среде со своими файлами, библиотеками и настройками. Контейнер использует ядро операционной системы компьютера, но не ставит программы «в систему» рядом с остальными.

Два главных объекта:

- **Образ** — готовый шаблон. В нём уже лежат сайт, сервер и нужные программы. Образ этого проекта называется `tamsun:latest`.
- **Контейнер** — запущенный экземпляр образа. Образ можно запустить много раз, каждый запуск — отдельный контейнер.

Образ собирается по инструкции в `Dockerfile`. Перед копированием файлов Docker читает `.dockerignore` и выбрасывает из контекста сборки всё, что там перечислено. Запуск, порт, пароль и место для базы описаны в `docker-compose.yml`. Compose сам вызывает сборку по `Dockerfile`.

Каждая инструкция `Dockerfile` создаёт слой. Если файл проекта изменился, а предыдущие слои нет, Docker берёт их из кэша и заново выполняет только хвост. Поэтому зависимости ставятся до копирования исходников: правка страницы не заставляет заново скачивать пакеты.

Сервер внутри контейнера — тот же файл `server.ps1`, что и при обычном запуске. Меняется окружение: Linux внутри контейнера, а не Windows на компьютере.

## 3. Из чего состоит упаковка

| Файл | Зачем |
| --- | --- |
| `Dockerfile` | Пошаговая сборка образа: сначала сайт, потом среда, в которой работает сервер |
| `.dockerignore` | Список файлов, которые команда `COPY` не берёт с компьютера |
| `docker-compose.yml` | Запуск контейнера: имя образа, порт 8765, переменные, том с базой |

## 4. Файл Dockerfile

Файл читается сверху вниз. В нём два этапа. Слово `AS` даёт этапу имя. Итоговый образ — это последний этап, `runtime`. Этап `build` живёт только пока идёт сборка: из него в рабочий образ забирается одна папка `dist`.

### Этап сборки сайта

```dockerfile
FROM node:22-bookworm AS build
```

`FROM` начинает этап с готового образа. `node:22-bookworm` — официальный образ Node.js 22 на Debian 12 (кодовое имя bookworm). Внутри уже есть `node` и `npm`. `AS build` — имя этапа, на него потом ссылается `COPY --from=build`.

```dockerfile
WORKDIR /src
```

`WORKDIR` создаёт каталог `/src` внутри временного контейнера сборки и делает его текущим. Дальнейшие `COPY` и `RUN` выполняются в `/src`.

```dockerfile
COPY package.json package-lock.json ./
```

`COPY` берёт файлы с компьютера (из контекста сборки) и кладёт их в текущий каталог образа. Здесь копируются только два файла: описание зависимостей и точный замок версий. Исходники сайта на этом шаге ещё не копируются. Так слой с `npm ci` остаётся в кэше, пока не изменятся сами зависимости.

```dockerfile
RUN npm ci
```

`RUN` выполняет команду во время сборки, и её результат записывается в слой. `npm ci` ставит ровно те версии, которые записаны в `package-lock.json`. На этом этапе нужны и инструменты сборки: Vite лежит в `devDependencies`, без него `npm run build` не соберёт сайт.

```dockerfile
COPY . .
```

В `/src` копируется остальной проект. Точка слева — корень папки на компьютере, точка справа — текущий каталог `/src`. Состав копии уже урезан файлом `.dockerignore`: в образ не попадают `node_modules`, локальная `dist`, база, `.env` и отчёты.

```dockerfile
RUN npm run build
```

Скрипт `build` из `package.json` запускает `vite build`. Готовые страницы, стили и скрипты появляются в `/src/dist`. Этим этапом сборка сайта заканчивается.

### Этап рабочей среды

```dockerfile
FROM node:22-bookworm AS runtime
WORKDIR /app
```

Новый `FROM` начинает чистый образ. Слои этапа `build` в него сами не переносятся. Рабочий каталог теперь `/app`: здесь будут сервер, зависимости и сайт.

Дальше одна длинная команда `RUN`. Обратный слэш в конце строки только переносит текст, для Docker это одна инструкция и один слой. Шаги соединены через `&&`: если любой шаг завершится с ошибкой, сборка остановится и следующие команды не выполнятся.

По порядку эта команда делает следующее.

1. `apt-get update` обновляет список пакетов Debian.
2. `apt-get install` ставит `curl`, `unzip`, `ca-certificates` и `wget`. Флаг `--no-install-recommends` берёт только сами пакеты, без рекомендованных дополнений. Эти утилиты нужны, чтобы скачать PowerShell и SQLite и распаковать архив. `curl` ещё используется проверкой живости контейнера.
3. `wget` скачивает пакет репозитория Microsoft для Debian 12, `dpkg -i` его устанавливает. После второго `apt-get update` в списке пакетов появляется PowerShell.
4. `apt-get install powershell` ставит PowerShell 7. Команда сервера называется `pwsh`.
5. `curl` скачивает NuGet-пакет `Stub.System.Data.SQLite.Core.NetStandard` версии `1.0.119`. Это zip-архив с расширением `.nupkg`.
6. Архив распаковывается, и в `/opt/sqlite` копируются два файла: управляемая библиотека `System.Data.SQLite.dll` и машинный файл Linux `SQLite.Interop.dll` из папки `runtimes/linux-x64`. Сервер подключает их по переменной `TAMSUN_SQLITE_LIB`.
7. `rm -rf` удаляет архив, временную папку, пакет Microsoft и списки `apt`. Они нужны были только для установки. В слое образа остаётся результат: PowerShell и две библиотеки SQLite.

```dockerfile
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
```

В рабочий образ зависимости ставятся заново, уже с флагом `--omit=dev`. Vite и прочие пакеты разработки не ставятся: сайт уже собран. В `dependencies` остаётся то, чем сервер пользуется в работе, в том числе `pdfkit` для счетов и каталога.

```dockerfile
COPY . .
COPY --from=build /src/dist ./dist
```

Первая строка копирует в `/app` сервер, скрипты, фотографии и видео. Вторая забирает из этапа `build` только собранный сайт и кладёт его в `/app/dist`. Локальная папка `dist` с компьютера в контекст не входит, поэтому готовые файлы появляются именно из первого этапа.

### Настройки, порт и команда запуска

```dockerfile
ENV TAMSUN_BIND=+
ENV TAMSUN_PORT=8765
ENV TAMSUN_SQLITE_LIB=/opt/sqlite
```

`ENV` записывает переменные в образ. Их читает `server.ps1`.

- `TAMSUN_BIND=+` заставляет сервер слушать все сетевые интерфейсы контейнера. Префикс получается `http://+:8765/`. Так проброс порта с компьютера доходит до процесса. Значение по умолчанию в скрипте — `127.0.0.1`, его внутри контейнера видит только сам контейнер.
- `TAMSUN_PORT=8765` задаёт порт. Скрипт принимает число от 1 до 65535.
- `TAMSUN_SQLITE_LIB=/opt/sqlite` указывает папку с библиотеками Linux. Без этой переменной скрипт искал бы SQLite в папке `lib` проекта, где лежат сборки для Windows.

```dockerfile
EXPOSE 8765
```

`EXPOSE` записывает в описание образа, что программа слушает порт 8765. Сам по себе этот порт на компьютере не открывается. Открытие делает поле `ports` в `docker-compose.yml`.

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 \
  CMD curl -fsS http://127.0.0.1:8765/api/catalog >/dev/null || exit 1
```

`HEALTHCHECK` — проверка изнутри контейнера.

- `--interval=30s` — повтор каждые 30 секунд;
- `--timeout=5s` — ждать ответ не дольше 5 секунд;
- `--start-period=20s` — первые 20 секунд после старта неудачи не считаются: серверу нужно время поднять базу;
- `--retries=3` — контейнер признаётся нездоровым после трёх неудач подряд.

Команда запрашивает `GET /api/catalog`. Этот адрес отдаёт каталог без пароля администратора, поэтому проверка не требует секрета. `curl -fsS` завершается с ошибкой, если страница не открылась или код ответа неуспешный. Вывод отбрасывается. При ошибке выполняется `exit 1`, и Docker помечает проверку как неудачную.

```dockerfile
CMD ["pwsh", "-NoProfile", "-File", "/app/server.ps1"]
```

`CMD` — команда, которой запускается контейнер. Форма в квадратных скобках передаёт аргументы напрямую, без оболочки. `pwsh` запускает PowerShell, `-NoProfile` не подгружает пользовательский профиль, `-File` выполняет `/app/server.ps1`. Пока этот процесс жив, жив и контейнер. Если скрипт завершится, контейнер остановится.

В начале `server.ps1` проверяется `ADMIN_PASSWORD`. Пустое значение даёт текст «Критическая ошибка: ADMIN_PASSWORD не задан в переменных окружения» и код выхода 1. В `Dockerfile` этот пароль не задаётся: его передаёт Compose в момент запуска.

Размер готового образа около 1,9 ГБ. В него входят Node.js, PowerShell, SQLite, собранный сайт, фотографии и видео мастерской.

## 5. Файл .dockerignore

Docker читает `.dockerignore` до инструкций `COPY`. Контекст сборки — это набор файлов папки проекта, который уходит в сборку. Строка в этом файле — шаблон исключения, похожий на шаблоны `.gitignore`. Исключённый файл физически остаётся на компьютере, в образ он просто не копируется.

Оба этапа используют `COPY . .`, поэтому список действует и на сборку сайта, и на рабочий образ.

| Строка | Что исключает и зачем |
| --- | --- |
| `node_modules` | Папка зависимостей с компьютера. На Windows в ней другие машинные файлы, чем в Linux. Внутри образа зависимости ставятся заново командой `npm ci`. |
| `dist` | Уже собранный сайт с компьютера. В рабочий образ попадает `dist` из этапа `build`, собранный внутри Linux. |
| `data` | Живая база `tamsun.sqlite`, журнал ошибок и загруженные файлы. Заказы этого компьютера не должны оказаться внутри образа. В запущенном контейнере папка `data` появляется отдельно, из тома. |
| `.git` | История Git. Для работы сайта она не нужна и увеличивает контекст сборки. |
| `.env` | Пароль администратора и ключ чата. Секрет, попавший в слой образа, остаётся в истории слоёв. Пароль передаётся только при запуске. |
| `open.txt` | Локальная служебная заметка, к работе сервера не относится. |
| `error-handling-audit.md` | Черновик разбора ошибок, не часть программы. |
| `*.md` | Все файлы Markdown, включая этот отчёт и `отчет.md`. Звёздочка означает любое имя, `.md` — расширение. |
| `lib/x64` и `lib/x86` | Сборки SQLite для Windows. В контейнере Linux сервер берёт библиотеки из `/opt/sqlite`, эти папки ему не подходят. |

Пустые строки Docker пропускает. Если шаблон совпал с файлом, `COPY` ведёт себя так, будто этого файла в папке нет.

## 6. Файл docker-compose.yml

Compose читает этот файл и одной командой собирает образ и запускает контейнер. Отступы задают вложенность: поля под `tamsun` относятся к одному сервису.

```yaml
services:
  tamsun:
```

`services` — список контейнеров проекта. Здесь он один, имя сервиса `tamsun`. По этому имени Compose называет контейнер и по нему же можно обращаться в командах.

```yaml
build: .
```

Точка — папка, где лежит `docker-compose.yml`. Из неё берётся контекст сборки и `Dockerfile`. Флаг `--build` у команды запуска заставляет пересобрать образ, если файлы изменились.

```yaml
image: tamsun:latest
```

Имя и метка готового образа. `latest` здесь просто метка, которую задал этот файл. Она сама по себе не скачивает образ из интернета: образ собирается локально полем `build`.

```yaml
ports:
  - "8765:8765"
```

Проброс порта записывается как `порт_компьютера:порт_контейнера`. Запрос на `127.0.0.1:8765` компьютера попадает на порт 8765 процесса внутри контейнера. Оба числа совпадают, чтобы адрес в браузере был тем же, что и при запуске `server.ps1` напрямую.

```yaml
environment:
  ADMIN_PASSWORD: ${ADMIN_PASSWORD:-}
  OPENAI_API_KEY: ${OPENAI_API_KEY:-}
  TAMSUN_BIND: "+"
  TAMSUN_PORT: "8765"
  TAMSUN_HOSTS: ${TAMSUN_HOSTS:-}
  TAMSUN_SQLITE_LIB: /opt/sqlite
```

`environment` задаёт переменные процесса `pwsh`. Запись `${ИМЯ:-}` означает: взять значение из окружения PowerShell, а если переменной нет — подставить пустую строку.

- `ADMIN_PASSWORD` — пароль админки. Пустая строка доходит до `server.ps1`, и процесс сразу завершается. Запасного пароля в коде нет.
- `OPENAI_API_KEY` — ключ чата. Пустое значение допустимо: магазин, корзина и заявки работают, консультант остаётся на локальных ответах.
- `TAMSUN_BIND` и `TAMSUN_PORT` повторяют значения из `Dockerfile`. Поле Compose перекрывает `ENV` образа на время этого запуска.
- `TAMSUN_HOSTS` — дополнительные имена сайта через запятую. `localhost`, `127.0.0.1` и `::1` сервер разрешает и без этой переменной. Чужое имя, например `evil.example`, получает ответ 403.
- `TAMSUN_SQLITE_LIB` снова указывает на `/opt/sqlite`, чтобы путь к библиотеке не зависел только от слоя образа.

Файл `.env` в образ не копируется. Если он лежит рядом с `docker-compose.yml`, Compose может подставить из него `${ADMIN_PASSWORD}` в момент запуска. Внутрь файловой системы контейнера этот файл при этом не попадает: `server.ps1` ищет `.env` в `/app`, а `.dockerignore` туда его не пускает.

```yaml
volumes:
  - tamsun-data:/app/data
```

Слева от двоеточия — имя тома, справа — папка внутри контейнера. Всё, что сервер пишет в `/app/data`, хранится в томе `tamsun-data`. Там лежит `tamsun.sqlite` и журнал `tamsun-error.log`.

Файлы самого контейнера исчезают вместе с ним. Том живёт отдельно:

- `docker compose down` останавливает и удаляет контейнер, том с заказами остаётся;
- `docker compose down -v` удаляет и контейнер, и том, то есть стирает базу.

При следующем запуске Compose подключает тот же том к новому контейнеру, и заказы на месте. В чистом томе каталог создаётся из начальных данных проекта.

```yaml
restart: unless-stopped
```

Если процесс сервера упал или компьютер перезагрузился, Docker поднимает контейнер снова. Остановка вручную через `docker compose down` этот автоматический запуск отменяет: слово `unless-stopped` как раз означает «пока контейнер не остановлен человеком».

```yaml
volumes:
  tamsun-data:
```

Этот блок на верхнем уровне объявляет именованный том. Пустое значение после двоеточия значит, что Docker сам выбирает место на диске. Том не привязан к папке проекта, поэтому случайное удаление файлов рядом с `server.ps1` базу в томе не трогает.

## 7. Как запустить

На компьютере нужен Docker Desktop. В PowerShell, в папке проекта:

```powershell
$env:ADMIN_PASSWORD = "длинный-пароль"
docker compose up --build
```

Сначала в текущий сеанс PowerShell кладётся пароль. Затем `docker compose up` читает `docker-compose.yml`. Флаг `--build` запускает сборку: Docker применяет `.dockerignore`, выполняет `Dockerfile` и помечает результат как `tamsun:latest`. После этого создаётся контейнер, к нему подключается том `tamsun-data`, открывается порт 8765 и выполняется `CMD`.

Сайт: `http://127.0.0.1:8765/`.  
Админка: `http://127.0.0.1:8765/admin`.

Если порт 8765 уже занят локальным `server.ps1`, этот процесс нужно остановить. Два процесса не могут слушать один порт.

Остановка:

```powershell
docker compose down
```

## 8. Что проверено

Проверка выполнена на этой машине после сборки образа `tamsun:latest`.

| Проверка | Результат |
| --- | --- |
| Запуск без `ADMIN_PASSWORD` | Контейнер сразу останавливается, код выхода 1 |
| `GET /api/catalog` с заданным паролем | Ответ 200, в каталоге есть товар `bes-qaru` |
| Главная страница | Ответ 200 |
| Запрос с заголовком `Host: evil.example` | Ответ 403 |

Каталог в чистом контейнере создаётся из начальных данных проекта. Рабочая база с компьютера в образ не копируется.

## 9. Вывод

Три файла делят работу.

1. `Dockerfile` фиксирует порядок сборки: собрать сайт в этапе `build`, поставить PowerShell и SQLite в этапе `runtime`, запустить `server.ps1`.
2. `.dockerignore` не даёт `COPY` забрать секреты, чужие машинные файлы и живую базу.
3. `docker-compose.yml` подставляет пароль при запуске, открывает порт 8765 и хранит заказы в томе `tamsun-data`.

На компьютере достаточно Docker Desktop: Node.js, PowerShell и SQLite уже внутри образа.

Сайт в контейнере открывается по HTTP. Для публичного адреса сертификат HTTPS ставится на прокси перед контейнером, а имя сайта передаётся в переменную `TAMSUN_HOSTS`.
